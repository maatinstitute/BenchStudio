# Contributing

Issues, bug reports and pull requests are welcome. No individually signed
collaboration agreement, copyright assignment, CLA form or sign-off is required.

## Read the contribution terms

This project is research-use source-available software, not MIT-licensed or
OSI open-source software. Read [LICENSE](LICENSE), especially section 5, before
submitting code or documentation.

You retain ownership. Your submitted contribution is available to researchers
under the research license. You also grant Alba Maria Tellez Fernandez the
explicit non-exclusive rights in section 5 to maintain, commercially license,
transfer and relicense that contribution. Those additional rights allow the
project to accept contributions without negotiating an agreement for every PR.
They do not grant other users commercial rights.

Submit only material you can license on these terms, including any necessary
employer permission. Identify upstream code and preserve its original notices.
Existing separately signed contributor agreements are not replaced.

## Issues and patches

For bugs, include the package/revision, minimal reproduction, expected and actual
behavior, and relevant logs with credentials and private data removed.
For PRs, describe the change, add meaningful regression coverage where needed,
and report the local checks you ran. Keep unrelated changes separate.

Use the development installation and testing commands in [README](README.md).
Ordinary fixes do not require hosted CI, model downloads or simulator execution.
Do not include private datasets, credentials, model weights or unrelated licensed
code. Experiment execution permissions are separate from software licensing.

## Returning research modifications

Changes to this Software that you put into use must be offered upstream as a
reproducible patch or PR within 30 days and before publishing dependent results,
whichever comes first. Submission does not guarantee acceptance. This does not
require submission of independently written research code, data, or unused edits.
Contribution-only forks exist to submit changes; they do not authorize an
independent release or a rebranded academic distribution. Keep attribution and
make clear that modifications are not official releases. Read LICENSE sections
2 and 4 before sharing outside your own research team.

# BenchStudio implementation audit

This is a current-state audit of the roadmap in the private development
repository. “Verified” means covered by a local test or a directly inspected
artifact. It does not mean that an external simulator, checkpoint, or robot
has been evaluated.

| Scenario identity | Verified | `ScenarioPack` and deterministic content-addressed archives bind task revisions, lowercase SHA-256 asset and initial-condition identities, and success criteria before execution; standalone scenario archive verification plus creation/extraction reject symlinks, duplicate entries, traversal, corruption, and digest mismatches. |
| Evidence integrity | Verified locally | Artifact manifests, sibling anchors, external digest verification, optional detached Ed25519 signatures for manifests and runtime receipts, and safe archive extraction are implemented. Key custody and any remote trust service remain external. |
| Runtime execution receipts | Implemented | Each run writes a digest-verifiable receipt recording the frozen run/attempt/plan identity, worker, backend, clock domain, execution interval, and environment fingerprint; action evidence also preserves source/next timestamp values and uncertainty; receipts are included in artifact manifests. |
| Policy lifecycle and timing | Verified as contracts | Lifecycle, action semantics, clock domains, queue/drop/deadline, queue-order preservation, mixed-clock rejection, and replay conformance validators are tested. |

| Model adapter registry | Implemented | Policy adapters declare capabilities and dependencies, support optional entry-point discovery, can be instantiated directly from frozen model declarations, and include strict per-call and persistent JSON-line command bridges for independent policy runtimes; named `smolvla` and `opendm` VLA protocol bridges preserve external checkpoint ownership, while the digest-bound `trace` adapter requires and verifies frozen trace bytes before reference-policy campaigns through the simulator registry. Adapter-returned metadata is retained as deterministic per-action evidence. |
| Inference efficiency | Verified as instrumentation | Latency, observation age, action chunks, resource points, overhead, explicit timing clock/boundary/uncertainty provenance, Pareto helpers, and concrete synchronous/asynchronous/streaming/cached policy execution strategies are implemented; no production checkpoint result is claimed. |
| Execution overhead acceptance | Implemented | `audit_execution_overhead()` compares matched instrumented/uninstrumented samples, counts deadline misses, requires timing provenance for valid reports, and persists `benchstudio_execution_overhead_v1`; campaign audits automatically include `execution-overhead.json` when present. |
| Scientific acceptance contract | Implemented | `audit_evaluation_acceptance()` evaluates policy transparency, attempt integrity, reproducibility, recovery, timing, benchmark fidelity, statistical validity, evidence validity, and execution overhead. Missing evidence is reported as failed; the result serializes as `benchstudio_evaluation_acceptance_v1`, can be embedded in audited reports, and is available from the CLI with explicit JSON evidence or parity/recovery/statistics/reproducibility report inputs. |
| Paired statistics | Verified | Exact binomial and discordance intervals, matched deltas, missingness, standard errors, and fail-closed score-coverage termination semantics are exposed in analysis results. |
| Sim-to-real fidelity | Analysis-ready | Transfer gaps, failure-category agreement, observation-age summaries, ranking concordance, deterministic serializable fidelity reports, JSON/JSONL record loading, standalone CLI analysis, and `--transfer-backends SIMULATION=PHYSICAL` integration in campaign comparison reports are implemented; physical data is not present. |
| Benchmark validity provenance | Implemented | Frozen validity records cover task revision, dataset lineage, contamination review, exclusions, early termination, metric scope/revision, and metric stability; comparative audits gate invalid records. |
| Calibration provenance | Implemented at protocol boundary | Camera, action-transform, controller, physical-parameter, and clock calibration identities can be frozen per environment, compared for compatibility, and persisted in run manifests. |
| Robustness and recovery | Analysis-ready | Counterfactual pairing, frozen branch-lineage and outcome-contract audits, independently loaded plan validation, confirmation plans, missing-outcome bounds, exact recovery-rate uncertainty, versioned JSON/JSONL recovery reports, and recovery CLI support are implemented; no external disturbance campaign has been run. |
| Frozen counterfactual plans | Implemented | Nominal and intervention branches share frozen pair identities, receive deterministic branch IDs, and carry a separately validated counterfactual plan digest. |
| Counterfactual execution | Implemented | `execute_counterfactual_plan()` evaluates nominal and intervention branches through an external evaluator, preserves frozen branch lineage, writes deterministic evidence incrementally, and leaves missing or failed branches explicit for recovery. |
| Counterexample search integrity | Implemented | Search plans and result artifacts can be serialized, independently loaded, and validated for case identity, scenario consistency, parameters, duplicate/missing rows, and digest integrity; `execute_search_plan()` persists deterministic case results and exposes only observed failures as confirmation candidates. |
| Counterexample confirmation | Implemented | Confirmation plans and result artifacts can be independently loaded and validated for candidate/seed lineage, duplicates, and missing rows; `execute_confirmation_plan()` evaluates an independent holdout matrix, links results to the frozen search digest, and records failure reproduction separately from discovery evidence. |
| WorldEpisode binding | Boundary verified | The optional reference validator is used when installed; canonical and strict local validation bind expected episode/revision identities, validate nested clocks/action semantics/world traces/provenance with structured diagnostics, and normalize validator failures, while the fallback reports missing canonical metadata instead of fabricating it. |
| RoboChallenge integration | Observe-only verified | Opaque observation/action digests and acknowledgments are validated with explicit runtime type checks, duplicate and timestamp-order detection, optional execution timestamps, and deterministic protocol accounting; rejected messages remain sticky audit failures. Safety, execution, and official scoring remain external. |
| AlpaBridge integration | Telemetry verified | Driver telemetry schema and deadline/load-failure audits are dependency-free; AlpaSim serving remains external. |
| External simulator backends | MuJoCo, Gymnasium, Genesis, Isaac Lab, and external-process boundaries implemented; runtimes optional | Lazy adapters expose control/reset, state, timing, termination, caller-supplied success semantics, and explicit Gymnasium early-success termination; Genesis requires explicit scene/action/observation callbacks, while Isaac Lab preserves its vectorized reset/step/extras boundary through explicit environment-index selection. Optional backend extras are declared in `pyproject.toml` and readiness is checked before scheduling. Registry-backed MuJoCo and Gymnasium closed-loop tests pass in the robotics simulation environment; the base environment skips them cleanly when optional runtimes are absent. Frozen plans can instantiate declared adapters through the registry, including a persistent JSON-line process bridge. The `mujoco`/`gymnasium`/`genesis-world`/Isaac Lab packages and pinned benchmark assets remain optional; physical execution still requires its own runtime and approvals. |
| Frozen backend requirements | Implemented | Environment declarations can pin an adapter and required authority capabilities; `CampaignExecutor` rejects unmet or unavailable requirements before scheduling attempts. |
| Adapter readiness reporting | Implemented | The CLI reports optional dependency availability and declared simulator/model capabilities before execution. |
| Registry-backed CLI execution | Implemented | `--execute-registry` instantiates the model and simulator adapters declared by the frozen campaign plan after readiness validation. |
| Sim-to-real statistical uncertainty | Implemented for matched records | Transfer reports preserve missing outcomes and now include an exact paired discordance confidence interval alongside the point gap and standard error. |
| RoboChallenge observe-only evidence | Implemented at protocol boundary | Validated opaque observation/action bytes are retained as canonical base64 plus SHA-256 digests, adapter event ordering, and duplicate/replay diagnostics; rejected-message failures are retained in the audit; execution and official scoring remain external. |
| End-to-end campaign audit | Implemented | `CampaignExecutor.audit()` independently rechecks artifact manifests and frozen runtime receipt identity, then validates ledger completeness, calibration compatibility, and claim prerequisites in one path. |
| Outcome provenance persistence | Implemented | Plan-bound `OutcomeLedger` persists official, declared, or supplementary scorer records with schema, digest, duplicate, and frozen-attempt validation; executor audits reopen it automatically. |
| Audited evaluation reports | Implemented | Reports can serialize campaign audit decisions, outcome provenance, and paired uncertainty together, preserving qualified/unsupported claim context offline. |
| Distributed lease recovery | Implemented for filesystem workers | Expired leases are reclaimable by the next worker, active leases can be renewed by their owner, ownership checks remain enforced, and ledger commits are serialized with a cross-process file lock so stale worker state cannot duplicate an attempt. Physical jobs still require explicit no-retry policy. |
| Multi-worker campaign execution | Implemented | `CampaignExecutor.run_parallel()` assigns frozen attempts through filesystem leases and returns a plan-ordered aggregate after all workers refresh the shared ledger. |
| Scheduler batch dispatch | Implemented | `CampaignExecutor.run(attempt_ids=...)` accepts only IDs from the frozen plan, enabling external GPU/container schedulers to dispatch explicit batches while retaining ledger recovery and evidence checks. |
| Checkpoint provenance | Implemented | Frozen checkpoint digests, model adapters, architectures, and robot profiles are copied into attempt manifests without copying private adapter configuration paths. |
| Campaign evidence bundles | Implemented | Deterministic, content-addressed ZIP bundles include frozen plans, ledgers, manifests, and attempt evidence; standalone verification checks trusted digests, required files, duplicate names, symlinks, corruption, traversal paths, frozen-plan digests, complete frozen-attempt ledger coverage, ledger identity/digest consistency, allowed failure statuses, and evidence-flag semantics before extraction. |
| Artifact publication | Implemented | `ArtifactStore`, `LocalArtifactStore`, and vendor-neutral `HttpArtifactStore` publish and retrieve deterministic campaign bundles by digest with atomic local writes, digest verification, safe extraction, and idempotent retry behavior; cloud credentials and authorization remain external. |
| CLI campaign workflow | Implemented | Declarative mock or registry execution can audit its ledger, write immutable bundles, distribute frozen attempts with `--workers`, publish to local or HTTP artifact stores, and compare frozen policy traces from one command. |
| SmolVLA/DM0.5 parity | Harness ready, frozen trace path verified, external run pending | Persistent external policy runtime, digest-bound `TracePolicy`, direct frozen JSONL trace comparison, and a registry-backed frozen trace campaign with action/metadata/observation-binding evidence are implemented; no checkpoint is bundled or silently downloaded. |
| CI workflow | Prepared locally, not uploaded | `.github/workflows/ci.yml` exists locally. GitHub rejected its upload because the current OAuth token lacks workflow scope; source and smoke tests are published. |
| Python compatibility | Locally verified | Python 3.10.12 compiles and imports the package; the full pytest suite runs under the configured Python 3.13 environment. |

The repository remains private and proprietary. External benchmark scoring,
physical safety, emergency stops, and hardware authorization are intentionally
not inferred from BenchStudio evidence.
